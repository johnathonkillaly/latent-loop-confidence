# Evaluation protocol

The procedural dataset is seeded and versioned. Every generated answer is checked by an independent structured reference solver. Split hashes, instance IDs, tokenization checks, exact duplicate audit, and a token 13-gram Jaccard audit are recorded. Symbol pools are split-specific; starting numeric residues differ; OOD extends numeric range and sequential-task depth. Templates are shared intentionally, so held-out instances do not imply held-out task formats.

The initial prompt produced primarily prose at the first answer token. All initial training/evaluation results are retained. Seven fixed answer prefixes were audited on the first 60 training examples. `Answer: (` gave the highest training conditional accuracy and mostly produced valid letter argmaxes; it became the primary format. Hyperparameters otherwise stayed fixed. This development history makes the study exploratory, even though no test answers were used for prefix, model, checkpoint, threshold, or fusion selection.

All variants receive the same candidate list in the prompt. Primary scores condition on four label tokens. The baseline is the argmax among those four; full-vocabulary next-token accuracy is a separate format diagnostic. Four-option shortlist coverage is mechanically 100%; the top-two reranker records a nontrivial coverage limit. Candidate information is available to the original model as well as the learned reranker.

Training uses candidate correctness BCE for confidence, option CE for refinement, and future-loss-opportunity BCE for continuation. The heads consume cached, label-free backbone features. Training and validation labels supervise fitting and selection only. Test/OOD labels are consulted exclusively for final metrics and explicitly labeled oracle diagnostics. The oracle horizon is four during continuation fitting. It is not secretly extended to eight during live stopping.

Validation selects the lowest-loss checkpoint. Fixed recurrence depth selects accuracy first and NLL second within 1–4. Fusion chooses among six fixed coefficients by validation accuracy/NLL. Temperature minimizes validation NLL. Margin and entropy calibrators fit validation correctness. Stopping chooses the least expensive threshold whose validation NLL is within 0.01 of the selected fixed model; if none qualifies it chooses the threshold minimizing validation NLL. This fallback correction postdates the archived initial experiment and is recorded.

Accuracy, conditional NLL, multiclass Brier, correctness Brier, 10-bin ECE, AUROC, selective accuracy, and risk-coverage are separate metrics. Wrong-to-right and right-to-wrong transitions compare exactly the same held-out items. State changes and cosine similarities describe representation movement, not reasoning correctness. Stopping metrics distinguish current error from improvement opportunity. All variants and depths are retained, including negative controls and extrapolation failures.

Three seeds vary auxiliary initialization and minibatch order. The 600 test items are shared across seeds; seed results are not independent test observations. Item bootstrap resamples shared instances while keeping the seeds together. An additional hierarchical bootstrap resamples both seeds and items, but three seeds are too few to characterize training variance precisely. Exact per-seed McNemar tests are recorded; no multiple-comparison correction is made. Conclusions favor comparisons against the one-pass controls rather than only against the frozen model.

Latency uses batch one, three warmups, explicit MLX synchronization, and 20 repetitions. Fixed heads use one cached validation example; live adaptive stopping uses 12 validation examples. Backbone timing uses the same 12 examples separately, including full-vocabulary final projection. Costs are not equated with measured FLOPs, and head latency is not called end-to-end latency. Width 256 approximately matches four width-64 loops' matrix operations while adding more parameters. The width-64 one-pass head matches no-memory recurrence parameter count.
