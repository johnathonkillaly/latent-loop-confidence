# Reproduce Experiment 5.1 locally

This branch is local research awaiting review. Do not push it or move `v0.1.0`.

Use the existing isolated Python 3.12 environment on Apple Silicon, with MLX 0.32.3 and mlx-lm 0.32.0. Core dataset/oracle tests and report regeneration need only the project's CPU dependencies. No new dependencies or upgrades are needed. Install from a fresh checkout with `python -m pip install -e '.[apple,test]'` on a compatible Mac, or `-e '.[test]'` for CPU checks/reports. A CPU-only environment cannot train these MLX models.

## Fresh reproduction

Run in a NEW checkout/run copy. Existing dataset manifests and frozen protocols deliberately refuse overwrite. Historical experiment results and public release files need no modification. Copying only tracked files is sufficient; the ignored adapters must be regenerated for inference.

```sh
python -m latent_loop.planning generate
python -m latent_loop.planning train --pilot --epochs 3
python -m latent_loop.planning train-all
python -m latent_loop.planning.analysis gradients
python -m latent_loop.planning.qwen validate
python -m latent_loop.planning.qwen train-all
python -m latent_loop.planning freeze
python -m latent_loop.planning evaluate
python -m latent_loop.planning rollout
python -m latent_loop.planning.analysis representations
python -m latent_loop.planning.demonstrations
python -m latent_loop.planning.qwen evaluate
python -m latent_loop.planning.qwen_analysis
python -m latent_loop.planning snake
python -m latent_loop.planning.snake_training generate
python -m latent_loop.planning.snake_training train
python -m latent_loop.planning.snake_training evaluate
python -m latent_loop.planning.snake_training episodes
python -m latent_loop.planning.snake_diagnostics
python -m latent_loop.planning report
python -m latent_loop.planning.verify
```

For a fresh rerun, remove ONLY the new Experiment 5b output/manifest/lock files in that disposable copy, preserving `config.json`, `plan.md`, this README and `start_receipt.json`; retain the original local research repository. The generator is deterministic and all eight compressed dataset files were regenerated byte for byte in an independent CPU-only environment. Training can resume at completed epoch boundaries with the same command: last adapter/model weights, optimizer state, seeded epoch ordering and best validation checkpoint are saved in `artifacts/experiment_05b/checkpoints/`. Partial interrupted epochs are repeated from the last completed epoch. Altering a training signature requires a new run.

Grid fitting: 3,600 layouts, validation 600, seeds 11/22/33, batch 64, 20 epochs, AdamW 0.001, weight decay 0.0001, gradient clip 1. Qwen uses the same fixed first 720 training /120 validation examples for both adapters, three epochs, batch 4, AdamW 0.0005, weight decay 0.01, clip 1. All hyperparameters and split seeds are in [config.json](config.json). This is a small pilot, not a large training sweep. Multiple full model forwards are timed, never cached feature scoring.

Qwen3-0.6B uses the exact historical revision `c1899de289a04d12100db370d81485cdf75e47ca`. The existing `get_model()` requires an already downloaded Hugging Face snapshot, converts to FP32 and freezes original weights. To populate a missing cache:

```sh
python -c "from huggingface_hub import snapshot_download; snapshot_download('Qwen/Qwen3-0.6B', revision='c1899de289a04d12100db370d81485cdf75e47ca', allow_patterns=['*.json','*.safetensors','*.txt','*.jinja'])"
```

Weights are downloaded separately under their Apache-2.0 license and are never committed. No remote workstation is needed. Set memory/runtime/data/epochs in the configuration BEFORE a new prospective run; do not mutate a consumed lockbox. The original run used a 48 GiB MLX limit and remained under six hours. Keep time for evaluation/reporting. Check significant local resource contention before fitting; never terminate unrelated work.

## Report-only reproduction

```sh
python -m latent_loop.planning report
```

This reads public recorded logits, metrics, demonstrations and rollout trajectories, requires neither MLX nor checkpoints, and creates Markdown, self-contained HTML and figures. Fresh hidden-state extraction, interventions, model inference and retraining require the regenerated ignored checkpoints. Snake includes an initial simulator smoke and a separate prospective 12-fit neural comparison, with its own fresh split manifest and freeze. Preserve `snake_config.json` when preparing a disposable rerun; remove only its generated manifests/outputs/lock in that copy. Snake uses 3,600/600/600 states, three seeds, 20 epochs, four conditions (safety recurrence, planning recurrence, one-block and four-block planning feedforward). Do not interpret the initial straight-body smoke distribution as the bent-body/obstacle neural benchmark.

`python -m latent_loop.planning qwen-train --condition qwen_recurrent --seed 11` trains/resumes a single recurrent transformer seed; use `--condition qwen_onepass` for its control. Single grid fits use `train --condition rec_simultaneous --seed 11`. Freeze/verification of live checkpoints requires the regenerated ignored adapters. Report-only regeneration and the public numerical audit require no adapters.

The Qwen execution receipt originally used an absolute source-path dictionary key. The review copy normalizes that key to a repository-relative path, retains every frozen content hash and timestamp, and records the privacy amendment; the verified original receipt remains in ignored artifacts. The scanner excludes its own literal detection patterns. No credentials were found. Reproduction on a new machine can produce a different local path in a freshly generated receipt; normalize that metadata before sharing it.
